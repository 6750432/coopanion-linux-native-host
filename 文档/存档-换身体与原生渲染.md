存档：换身体 / 丢开 Chromium（**只存档，不做**）
================================================================
为什么存这一档
    现在她的内存是 **613 MB / 2 个进程**，其中 **383 MB 是 QtWebEngine 的地板**
    （空白页 + 单进程实测，见 docs/瘦身实测.md）。
    也就是说 62% 的内存花在「跑一个 Chromium」上，而她本体只占屏幕 117×117 像素。
    想突破 400 MB，只有两条路，都是大工程 —— 记在这里，等哪天有空再做。

路线一：用 Qt 原生绘制替掉浏览器渲染（收益最大）
----------------------------------------------------------------
    现状：她是一个 Live2D 式的骨骼模型 ——
      · web/rig/rig.js（8 KB）：小型渲染器。每个部件是一张贴图铺在网格上，网格点逐帧经过
        变形器链（rot 绕枢轴转 / 缩放 / 平移 / warp 矩形位移场），WebGL2 绘制。
      · web/whale/figure.js（29 KB）：模型本身。把 createPet 每帧给的数据（腿角度、坐下程度、
        视线、眨眼、表情、说话幅度、横向惯性）换成变形器参数；后发、刘海、裙摆、尾巴、两只鲸鳍、
        呆毛、两只手臂各一个弹簧；眼睛和嘴每帧画进一张脸部贴图。
      · model.json：16 个部件的位置、枢轴、网格密度、贴图名。
    要做的事：把上面这套数学搬到 Python/Qt —— 用 QPainter 画同一组贴图，配上同一组网格变形
      （按网格切三角形 + 透视变换，或直接 QPainterPath 的手工变形），弹簧照抄。
    预估收益：613 MB → 大约 **150~200 MB**（Node 核心 110 MB + Qt 进程 40~80 MB）。
    预估代价：figure.js 里那些「手调出来的手感」要一模一样地复刻，最容易翻车的部分是
      头部视差、坐下时裙摆换图的那两三帧过渡、以及整套表情贴图的绘制时机。
      现实一点的估算是：先做「站着 + 眨眼 + 简单走动」，再做表情，最后做坐下/被拎/甩出去。
    其它代价：作者以后更新角色（新配色、新表情）都要手动移植；装扮页、气泡、菜单这些
      网页 UI 也得重画。

路线二：保留 Chromium，但把窗口从全屏改成「只围着她的小窗口」
----------------------------------------------------------------
    现在窗口是 1920×1080 的透明覆盖层，每帧软件合成 2 百万像素 —— 又费 CPU 又费内存。
    改成 400×400 左右、跟着她走的小窗口，理论上能省掉大部分合成开销（内存能省一些，
    CPU 省得多）。难点：页面的舞台坐标是按整屏算的，得给舞台加一个随窗口移动的位移、
    并且跟 pet-core 的位置同步；窗口频繁移动可能带来抖动或焦点问题。
    风险中等，收益偏 CPU（内存大概只降几十 MB），所以没有优先做。

路线三（顺带记一笔）：换身体 ≠ 换角色
    如果只是想「换一只」，不需要动渲染层 —— 照 examples/whale/README.md 里作者写的那条管线
    （母版立绘 → 按部件做编辑图 → ECC 仿射配准回母版 → 相减得遮罩 → 出部件贴图 → 每套配色重着色），
    用画图模型生成一张新的母版就能做。这条比前两条轻得多，但要美术和时间。

什么时候值得动
    只有在「内存真的不够用」或者「想让她常年挂机」的时候才值得。现在 613 MB 对这台 16G 的
    机器不算负担，所以先不做。
